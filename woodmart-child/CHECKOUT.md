# MITKIN: классическое оформление заказа

Переопределение для **WoodMart Child**, проверенное с WordPress 7.1.4, WoodMart 8.6.7, WooCommerce 11.3.0 и PHP 8.3. Шапка и подвал используют штатные шаблоны темы; их структура не изменяется. Общая текстовая типографика сайта задана как Times New Roman в `style.css`, включая Elementor и checkout; иконочные шрифты и админ-панель не заменяются.

## Применение

1. Разместить папку `woodmart-child` в `wp-content/themes/woodmart-child`, рядом с родительской темой `woodmart`, и использовать дочернюю тему.
2. Страница оформления заказа должна содержать `[woocommerce_checkout]`. На проверенном сайте это уже так. WooCommerce Checkout Block этими PHP-шаблонами не переопределяется. Назначенный макет Checkout Builder WoodMart пропускается на этой странице через штатный `woodmart_layout_id`; иначе он заменяет внешнюю форму, теряет классы оформления и повторно вызывает shipping/details. Настройки шапки, подвала и назначенных макетов в БД не меняются.
3. Очистить кеш страницы/ресурсов после обновления. CSS и JS имеют версию по `filemtime`.

Код не активирует тему, не меняет настройки магазина, тарифы, платёжные ключи, скидки, товары или существующие заказы. Публикация в GitHub сама по себе не подтверждает развёртывание файлов на WordPress.

## Состав

- `woocommerce/checkout/form-checkout.php`: две колонки, три секции и сводка заказа.
- `form-billing.php`: поля WooCommerce разделены на получателя и компактный адрес. Первое имя и фамилия сохраняются отдельными штатными полями. Страна скрыта в интерфейсе и задана как `RU` на клиенте и сервере; native country select сохранён для скриптов доставки. Компания удалена, вторая адресная строка объединена с основной. Ранее сохранённая квартира переносится в одну строку, без дублирования при последующих заказах. Населённый пункт располагается перед штатными способами доставки; область, адрес и индекс остаются ниже. Имя и фамилия идут одной строкой, телефон и почта — одной строкой на компьютере. Валидаторы индекса/области и неизвестные поля плагинов сохраняются. Здесь один раз вызывается `woocommerce_checkout_shipping`, поэтому повторно вызывать этот хук из `form-checkout.php` нельзя.
- `form-shipping.php`: дополнительный адрес с той же компактной схемой и один сворачиваемый комментарий вместо повторяющихся «Деталей». Обязательные дополнительные поля открывают блок автоматически, hooks shipping/order-notes сохраняются.
- `payment.php`: только доступные шлюзы WooCommerce и их родные `payment-method.php` / `payment_fields()`. Название кнопки по-прежнему может менять выбранный шлюз.
- `mitkin-place-order.php`: согласия, условия, фильтр HTML кнопки, хуки before/after submit и стандартный checkout nonce.
- `review-order.php`: действительная корзина, изображения, количества, метаданные, купоны, доставка, комиссии, налоги и итог.
- `inc/checkout.php`: подключение, ограничение checkout полной колонкой без sidebar, AJAX-фрагменты доставки и submit-блока, совместимость с таблицей WoodMart.
- `assets/css/checkout.css`, `assets/js/checkout.js`: оформление и подсветка выбранных вариантов. JS не перехватывает отправку, не рассчитывает суммы и не создаёт способы доставки/оплаты.

`woocommerce_before_checkout_form` (купон, вход, сообщения) и его формы находятся внутри общего `.mitkin-checkout` с `max-width:1440px`. Форма купона остаётся отдельным соседом `form.checkout`, поэтому нет вложенных форм и не ломается штатный coupon AJAX. На широких экранах купон, заголовок и колонки центрируются как единый блок. Для общего `style.css` и checkout-ресурсов используется версия по `filemtime`.

## Динамика и расширения

Доставка выводится штатной `wc_cart_totals_shipping_html()` с настоящими пакетами и тарифами. Сохраняются `shipping_method[]`, native cart-shipping markup, `woocommerce_after_shipping_rate` и before/after shipping hooks. Модули вроде СДЭК могут вывести свой выбор ПВЗ в штатном месте. Все доставочные пакеты обрабатываются WooCommerce, а не определяются по названию тарифа.

WooCommerce продолжает обновлять `.woocommerce-checkout-review-order-table` и `.woocommerce-checkout-payment`. Дополнительно заменяются `.mitkin-checkout-shipping-methods` и `.mitkin-checkout-place-order`: доступные тарифы, шлюзы, nonce и согласия не остаются от предыдущего AJAX-ответа. Фрагменты не содержат дублирующихся кнопок оплаты или shipping inputs.

Адресные поля можно дополнительно классифицировать фильтром `mitkin_checkout_is_address_field( $is_address, $key, $field )`. Неизвестные адресам поля плагинов остаются в секции получателя. Условная регистрация, пользовательские поля, отдельный shipping address и заметка заказа сохраняются.

Скидка «7%» не зашита в шаблон: показываются только реально применённые купоны/правила магазина. Нет фиксированных цен, тарифов, ПВЗ или «оплаты картой», если такой шлюз недоступен. Для виртуального заказа доставка не предлагается; бесплатный заказ не требует выбора шлюза.

## Проверки

На отдельном стенде с настоящими WordPress/WooCommerce и родительской темой выполнены:

- физическая корзина из трёх товаров, действительный процентный купон и item metadata;
- пересчёт итогов при переходе с самовывоза на курьера;
- поле тестового модуля ПВЗ на `woocommerce_after_shipping_rate`, сохранение его значения через AJAX;
- сохранение дополнительного обязательного поля плагина;
- исчезновение COD, когда доставка его не допускает; отказ сервером в подделанном запросе с недоступным шлюзом;
- сохранение согласия с условиями при AJAX-обновлении;
- ровно одна кнопка, payment region, shipping fragment и checkout nonce;
- успешный локальный заказ с банковским переводом, виртуальная и бесплатная корзины;
- адаптивность 390/768 px, JavaScript и PHP syntax checks.
- назначенный конфликтующий Checkout Builder layout не заменяет дочернюю форму; CSS действительно применён (радиус полей 12px), картинки ограничены по ширине;
- страна `RU` скрыта, компания/вторая строка отсутствуют, старая квартира сохранена, один блок комментария; локализация страны не восстанавливает старый порядок адресных полей.
- выравнивание купона при ширине 1440/1920/2560 px, применение и удаление купона через WooCommerce AJAX, Times New Roman для основных текстовых элементов.

Реальные API СДЭК и ЮKassa не вызывались. После развёртывания нужно проверить именно установленную версию каждого модуля в его тестовом режиме: выбор ПВЗ/адреса, сохранение данных доставки и переход к оплате. Базовая интеграция и хуки сохранены, но локальная проверка не подтверждает доступность внешних сервисов или их ключей.

Для повторения тестов см. `tests/checkout/README.md`. При обновлении WooCommerce сравнить указанные `@version` в переопределениях с новыми оригиналами.

Радиокнопки доставки и оплаты выровнены по центру первой строки названия через сетку; блоки ПВЗ и описания занимают всю ширину карточки. В «Ваш заказ» у каждой позиции есть доступная с клавиатуры кнопка удаления. Она использует штатную ссылку WooCommerce с nonce и возвратом на checkout: страница перезагружается, итоги пересчитываются, купон сохраняется. После удаления последней позиции WooCommerce переводит покупателя в пустую корзину. Проверены удаление всех трёх позиций и выравнивание радиокнопок при 390/1440 px.


## Компактное оформление, 27 ноября 2026

В файлах дочерней темы уменьшены заголовки, отступы, высота полей до 48 px и радиусы (6 px у полей, 10 px у панелей). Надпись и значок безопасности — графитовые. Двухколоночная композиция сохранена; имя и фамилия остаются рядом и на телефоне. Город вынесен перед способами доставки; значение и идентификатор штатного поля не изменены. Логотип ЮKassa скрывается только в заголовке её способа оплаты. Для действительного выбранного шлюза `cod` кнопка называется «Оформить заказ», для `yookassa_epl` — «Перейти к оплате». Другие шлюзы и бесплатные заказы сохраняют штатные подписи.

В работающем магазине через стандартный WooCommerce REST API применены именно настройки: `woocommerce_ship_to_destination=billing_only`, отключены методы зоны 1 `local_pickup:2` и `wpapiship_shipping:3`. Оставлен существующий `official_cdek:1`. Проверено, что гостевое оформление уже включено. Копии исходных настроек хранятся в рабочей сессии `/tmp/co28-{shipping,account,methods-1,gateways}.json` (не включать в публичный репозиторий).

ЮKassa в магазине отключена. Её включение, способы онлайн-оплаты и приоритет не изменялись. Настройки СДЭК для автоподстановки области/индекса, условий примерки, частичного выкупа и оплаты при получении через доступный API не подтверждены: эти возможности не подменяются кодом. Область/индекс и штатные виджеты выбора ПВЗ сохранены. Адресные поля не скрываются по строковому названию тарифа: их обязательность остаётся под управлением перевозчика и WooCommerce.

**Развёртывание:** изменения в PHP/CSS/JS подготовлены в репозитории, но не загружены на работающий WordPress. Доступен API администрирования, но нет подключения для развёртывания файлов темы. Не считать изменения файлов опубликованными по факту сохранения настроек магазина.

Проверки: PHP syntax, `node --check`, существующий интеграционный smoke test на одноразовых WordPress/WooCommerce (физическая/виртуальная/бесплатная корзина, серверная валидация, обновление доступности оплаты, локальный заказ, купоны и удаление товаров). Дополнительно проверены режим `billing_only`, отсутствие второго адреса, парные имена при 390 px, высота полей 48 px, радиус панели 10 px и кнопка оплаты при получении. Внешние API доставки и оплаты в локальном тесте не вызывались.
