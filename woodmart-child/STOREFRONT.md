# MITKIN: меню и боковая корзина

Меню изменены как обычные записи WordPress «Внешний вид → Меню», без подмены ссылок JavaScript/CSS. Обновлены используемое шапкой `main-navigation-fashion-2` и `mobile-navigation`. Пять пунктов по явному запросу пользователя имеют приоритет над разными вариантами шапки в PDF:

| Пункт | Ссылка |
| --- | --- |
| Новинки | `/shop/?orderby=date` |
| Одежда | `/shop/` |
| Образы | `/#looks` |
| О бренде | `/#about` |
| Журнал | `/blog/` |

Последние три ссылки ведут на существующие разделы/страницу; новые материалы журнала не создавались. Прежние пункты с демонстрационными мегаменю перемещены в неназначенное меню `mitkin-navigation-archive`, а не удалены. Назначение текущих меню и Header Builder сохранены.

Конфигурация хранится в `config/navigation.json`. Скрипт `tools/sync-navigation.py` использует штатный REST API WordPress, переменные окружения `WORDPRESS_URL`, `WORDPRESS_USERNAME`, `WORDPRESS_APP_PASSWORD`. Без аргументов только показывает план; `--apply` применяет изменения и перечитывает результат. Повторный запуск для совпадающего меню ничего не меняет. Пароли в репозитории не сохраняются.

`inc/storefront.php`, `assets/css/storefront.css` и `assets/js/storefront.js` подключаются дочерней темой. Для активации изменений корзины нужно развернуть эти файлы вместе с `functions.php` в активной Woodmart Child. Изменение меню уже записано в базу WordPress и отдельно от Git-развёртывания файлов темы.

Боковая корзина остаётся штатной WoodMart/WooCommerce: те же позиции, вариации, количества, удаление и AJAX fragments. Одна основная кнопка ведёт на checkout. Дополнительная «Просмотр корзины» удалена штатным хуком, остальные ссылки на корзину ведут на checkout. Внутренняя корзина WooCommerce и назначенная ей страница не удаляются: перенаправляется только её публичный экран. Для пустой корзины целевой экран — каталог; endpoint оплаты/спасибо исключён из перенаправления пустого checkout, поэтому нет цикла cart ↔ checkout.

При проверке исходного сайта один клик отправлял один запрос, ответ занял примерно 3,4 с. Не заявляем ускорение сервера: панель теперь открывается сразу с состоянием «Добавляем товар…», пока WooCommerce рассчитывает корзину. До ответа checkout недоступен, чтобы не переходить со старой суммой. После ответа подставляются настоящие fragments. Открытие идемпотентное: стандартное переключение WoodMart после добавления отключено фильтром опции, поэтому ответ не закрывает уже открытую панель. Ошибка запроса снимает состояние ожидания и сообщает о повторной попытке.

Основная палитра: оливковый `#484F32`, тёмный `#292E24`, фон `#F8F5EF`, песочный `#EEE7D9`. Стили применяются также к стандартным commerce-кнопкам и уведомлениям. На мобильном ширина панели ограничена экраном, для reduced motion отключена анимация индикатора.

Проверка: `tests/checkout/storefront.cjs` на отдельном локальном WordPress/WooCommerce. Для сайта с простыми permalink можно задать `CHECKOUT_TEST_CART_PATH`, `CHECKOUT_TEST_SHOP_PATH`, `CHECKOUT_TEST_CHECKOUT_PATH`. Основной checkout regression — `tests/checkout/smoke.cjs`. На рабочем сайте проверено настоящее меню; реальные заказы и платежи не отправлялись.
